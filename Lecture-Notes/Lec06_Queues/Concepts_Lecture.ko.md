## 1. 큐 ADT

### 1.1 정의

**큐(queue)** 는 다음과 같은 선형 리스트이다:
- 삽입(push, enqueue)은 **후단(rear)** 에서만 수행한다.
- 삭제(pop, dequeue)는 **전단(front)** 에서만 수행한다.

이는 **FIFO**(First In, First Out) 원칙을 따른다.

큐도 스택처럼 특별한 종류의 선형 리스트이며, 한쪽 끝을 전단, 다른 쪽 끝을 후단이라 한다. 버스 정류장의 줄이 큐의 예이다. 먼저 온 사람이 줄의 앞(전단)에서 먼저 버스에 타고, 새로 온 사람은 줄의 뒤(후단)에 선다.

```text
            +---+---+---+---+
  pop <---  | A | B | C | D |  <--- push
            +---+---+---+---+
              ^           ^
            front        rear
```

*그림 1. 전단에서 삭제하고 후단에 삽입하는 큐*

> **핵심:** 스택에서는 push와 pop이 모두 탑에서 이루어진다(LIFO). 큐에서는 push는 후단에서, pop은 전단에서 이루어진다(FIFO).

### 1.2 주요 연산

| 연산 | 설명 | 시간 복잡도 |
|------|------|------------|
| `push(x)` / `enqueue(x)` | 후단에 원소 삽입 | $O(1)$ |
| `pop()` / `dequeue()` | 전단에서 원소 삭제 | $O(1)$ |
| `front()` | 전단 원소 반환 | $O(1)$ |
| `back()` | 후단 원소 반환 | $O(1)$ |
| `empty()` | 큐가 비어있는지 확인 | $O(1)$ |
| `size()` | 원소의 개수 반환 | $O(1)$ |

*표 1. 큐의 주요 연산과 시간 복잡도*

표의 시간은 원형 배열(3절)이나 연결 리스트(4절)로 구현했을 때의 시간이다. 단순한 배열 표현에서는 2절에서 보듯이 pop이 $O(n)$이 될 수 있다.

## 2. 배열 기반 큐

### 2.1 단순 배열 큐

`front`를 왼쪽 끝, `rear`를 오른쪽 끝으로 사용한다.
- `front`는 항상 0이다.
- `push(x)`는 `queue[++rear] = x`이며 $O(1)$이다.
- `pop()`은 모든 원소를 왼쪽으로 이동하므로 $O(n)$이다.

`pop()` 연산이 $O(n)$의 이동을 요구하므로 비효율적이다.

이 표현은 큐의 $i$번째 원소($i$는 1부터)를 단순한 위치 공식 $\text{location}(i) = i - 1$에 따라 저장한다. 즉 첫 번째 원소는 `queue[0]`, 두 번째 원소는 `queue[1]`에 있다. `front`는 항상 0이고, `rear`는 마지막 원소의 위치이며, 큐의 크기는 `rear + 1`이다.

```text
(a) initial         front=0, rear=2   | A | B | C |   |   |
(b) after pop()     front=0, rear=1   | B | C |   |   |   |
(c) after push(D)   front=0, rear=2   | B | C | D |   |   |
                                       [0] [1] [2] [3] [4]
```

*그림 2. 단순 위치 공식을 쓰는 배열 큐의 pop과 push*

이 큐는 3강의 배열 선형 리스트(`ArrayLinearList`)에서 유도할 수 있다. 리스트의 왼쪽 끝을 전단, 오른쪽 끝을 후단으로 두면 각 연산은 다음과 같다.

| 큐 연산 | 배열 선형 리스트 연산 | 시간 |
|:-----|:-----|:-----|
| `Queue.empty()` | `ArrayLinearList.empty()` | $O(1)$ |
| `x = Queue.front()` | `ArrayLinearList.get(0)` | $O(1)$ |
| `x = Queue.back()` | `ArrayLinearList.get(listSize - 1)` | $O(1)$ |
| `Queue.push(x)` | `ArrayLinearList.insert(listSize, x)` | $O(1)$ |
| `Queue.pop()` | `ArrayLinearList.erase(0)` | $O(\text{listSize})$ |

*표 2. 배열 선형 리스트에서 유도한 큐 연산과 시간*

pop이 $O(\text{listSize})$인 이유는 첫 원소를 지운 뒤 나머지 원소를 모두 한 칸씩 왼쪽으로 옮겨야 하기 때문이다. 모든 연산을 $O(1)$에 수행하려면 큐에 맞춘 배열 표현이 필요하다.

### 2.2 수정된 위치 공식

`front`가 오른쪽으로 이동할 수 있는 수정된 위치 공식을 사용한다.
$$\text{location}(i) = \text{location}(1) + i - 1$$

- `pop()`은 `front`를 1 증가시키며 $O(1)$이다.
- 문제점: `rear = MaxSize - 1`이고 `front > 0`일 때, 전단의 공간이 낭비된다.

여기서 $\text{location}(1)$은 첫 번째 원소의 배열 위치이다. 이 공식을 쓰면 다음과 같이 동작한다.

1. 원소를 삭제할 때마다 큐 전체를 한 칸씩 왼쪽으로 옮길 필요가 없다.
2. 대신 삭제할 때마다 `front`가 오른쪽으로 1 이동한다.
3. `front`는 $\text{location}(1)$, `rear`는 마지막 원소의 위치이며, 빈 큐는 `rear < front`인 상태이다.

```text
             front       rear
               |           |
               v           v
+-----+-----+-----+-----+-----+-----+
|     |     |  B  |  C  |  D  |     |
+-----+-----+-----+-----+-----+-----+
 Q(0)  Q(1)  Q(2)  Q(3)  Q(4)  Q(5)
```

*그림 3. 수정된 위치 공식에서 첫 원소가 Q(2)에 있는 큐*

그림에서 $\text{location}(1) = 2$이므로 두 번째 원소의 위치는 $\text{location}(2) = 2 + 2 - 1 = 3$, 즉 Q(3)의 C이다. 여기서 B와 C를 삭제하면 `front`가 4로 움직여 D만 남고(`front = rear = 4`), D까지 삭제하면 `front = 5 > rear = 4`가 되어 빈 큐가 된다.

### 2.3 큐 이동

`rear = MaxSize - 1`이고 `front > 0`이면 배열의 앞쪽에 빈칸이 있어도 더 추가할 수 없다. 계속 추가하려면 모든 원소를 배열의 왼쪽 끝으로 옮기는 **큐 이동(shifting)** 을 해야 한다.

```text
(a) before shift   |   |   |   | A | B | C | D | E |
(b) after shift    | A | B | C | D | E |   |   |   |
```

*그림 4. 배열의 오른쪽 끝에 닿은 큐를 왼쪽 끝으로 옮기는 이동*

그러나 이동 때문에 최악의 경우 추가 시간이 $\Theta(1)$에서 $\Theta(n)$으로 늘어난다. 따라서 더 나은 방법이 필요하며, 그것이 3절의 원형 큐이다.

## 3. 원형 큐

### 3.1 개념

나머지(modulo) 연산을 사용하여 배열을 **원형**으로 취급한다.

$$\text{location}(i) = (\text{location}(1) + i - 1) \% \text{MaxSize}$$

삽입과 삭제 연산이 모두 $O(1)$이 된다.

이 방식을 **원형 큐(circular queue)** 라 하며, 최악의 경우에도 삽입과 삭제가 $\Theta(1)$이다. 1차원 배열 `queue[]`를 그대로 쓰되, 마지막 위치 다음에 위치 0이 온다고 보고 배열을 원으로 생각한다.

```text
          [2] ----> [3]
           ^          |
           |          v
          [1]        [4]
           ^          |
           |          v
          [0] <---- [5]
```

*그림 5. 크기가 6인 배열을 시계 방향의 원으로 본 모습*

원소가 3개인 원형 큐는 예를 들어 다음 두 가지로 배치될 수 있다.

| 배치 | `front` | 원소의 위치 | `rear` |
|:-----|:-----|:-----|:-----|
| 배치 1 | 1 | A는 [2], B는 [3], C는 [4] | 4 |
| 배치 2 | 4 | A는 [5], B는 [0], C는 [1] | 1 |

*표 3. 원소가 3개인 원형 큐의 두 가지 배치*

배치 2에서는 원소가 배열의 끝 [5]에서 [0]으로 이어진다. 원형으로 보면 A, B, C가 시계 방향으로 연속해 있다.

### 3.2 구현 세부사항

- **시계 방향 이동:** `rear = (rear + 1) % capacity`로 한 칸 이동한다(`capacity`는 배열 `queue`의 길이이다).
- 정수 변수 `theFront`와 `theBack`을 사용한다:
  - `theFront`는 첫 번째 원소에서 반시계 방향으로 한 칸 떨어진 위치이다.
  - `theBack`은 마지막 원소의 위치이다.
- 처음에는 `front = rear = 0`으로 초기화한다.

그림과 코드에서는 `theFront`와 `theBack`을 각각 `front`와 `rear`로 쓴다. 시계 방향 이동은 `rear`를 1 늘린 뒤 `rear == capacity`이면 `rear = 0`으로 되돌리는 것과 같다. 2.2절에서는 `front`가 첫 원소의 위치였지만, 원형 큐에서는 `front`가 첫 원소의 한 칸 앞을 가리킨다는 점에 주의해야 한다. 표 3의 배치 1에서 첫 원소 A는 [2]에 있고 `front`는 그 한 칸 앞인 1이다.

### 3.3 가득 참(Full) vs. 비어 있음(Empty) 구분

- 삽입으로 큐가 가득 찰 때: `front == rear`.
- 삭제로 큐가 비게 될 때: `front == rear`.

`front`와 `rear`만으로는 가득 찬 상태와 비어 있는 상태를 **구분할 수 없다**.

표 3의 배치 2에서 출발하여 삭제를 세 번 하면 다음과 같이 큐가 빈다.

| 연산 | `front` | `rear` | 남은 원소 (위치) |
|:-----|:-----|:-----|:-----|
| 시작 | 4 | 1 | A [5], B [0], C [1] |
| `pop()`으로 A 삭제 | 5 | 1 | B [0], C [1] |
| `pop()`으로 B 삭제 | 0 | 1 | C [1] |
| `pop()`으로 C 삭제 | 1 | 1 | (없음) |

*표 4. 원형 큐를 비우는 과정*

같은 배치에서 출발하여 여섯 칸을 모두 채우면 다음과 같다.

| 연산 | `front` | `rear` | 원소 (위치) |
|:-----|:-----|:-----|:-----|
| 시작 | 4 | 1 | A [5], B [0], C [1] |
| `push(D)` | 4 | 2 | A [5], B [0], C [1], D [2] |
| `push(E)` | 4 | 3 | A [5], B [0], C [1], D [2], E [3] |
| `push(F)` | 4 | 4 | A [5], B [0], C [1], D [2], E [3], F [4] |

*표 5. 원형 큐의 여섯 칸을 모두 채우는 과정*

연속된 삭제로 큐가 비면 `front = rear`가 되고, 큐가 처음 만들어졌을 때도 비어 있으므로 `front = rear = 0`으로 초기화한다. 그런데 연속된 삽입으로 큐가 가득 차도 `front = rear`가 된다. 따라서 두 상태를 구분하는 방법이 필요하다.

**해결 방법:** 한 칸을 낭비한다. 큐가 가득 찬 상태는 `(rear + 1) % capacity == front`일 때이다. 이는 최대 $\text{capacity} - 1$개의 원소를 저장할 수 있음을 의미한다.

이 방법은 큐가 가득 차지 않게 하는 방법의 하나이다. 두 상태를 구분하는 방법은 다음과 같다.

1. **큐가 가득 차지 않게 한다.** 원소를 추가하면 큐가 가득 차게 될 때 그 추가를 거부하면 위의 한 칸 낭비 방식이 되고, 그 대신 배열 크기를 늘리면 큐가 가득 찬 상태에 이르지 않는다.
2. **불 변수 `lastOperationIsAdd`를 둔다.** 추가 연산 뒤에는 이 변수를 `true`로, 삭제 연산 뒤에는 `false`로 둔다. 큐는 `(front == rear) && !lastOperationIsAdd`일 때 비어 있고, `(front == rear) && lastOperationIsAdd`일 때 가득 차 있다.
3. **원소 수 변수 `NumElements`를 둔다.** 추가 연산 뒤에는 이 변수를 1 늘리고, 삭제 연산 뒤에는 1 줄인다(0 아래로는 내려가지 않는다). 큐는 `(front == rear) && NumElements == 0`일 때 비어 있고, `(front == rear) && NumElements != 0`일 때 가득 차 있다. 이는 `NumElements == capacity`와 같다.

| 방법 | 빈 큐의 조건 | 가득 찬 큐의 조건 | 저장할 수 있는 원소 수 |
|:-----|:-----|:-----|:-----|
| 한 칸 낭비 | `front == rear` | `(rear + 1) % capacity == front` | `capacity - 1` |
| 배열 크기 늘리기 | `front == rear` | 가득 차기 전에 배열을 늘림 | 메모리가 허락하는 만큼 |
| `lastOperationIsAdd` | `front == rear && !lastOperationIsAdd` | `front == rear && lastOperationIsAdd` | `capacity` |
| `NumElements` | `NumElements == 0` | `NumElements == capacity` | `capacity` |

*표 6. 가득 찬 큐와 빈 큐를 구분하는 방법의 비교*

### 3.4 삽입 연산 (Enqueue)

원소를 추가할 때는 먼저 `rear`를 시계 방향으로 한 칸 옮긴 뒤, `queue[rear]`에 원소를 넣는다.

```cpp
void push(const T& element) {
    int newRear = (rear + 1) % capacity;
    if (newRear == front)
        throw std::overflow_error("Queue is full");
    rear = newRear;
    queue[rear] = element;
}
```

이 코드는 한 칸 낭비 방식을 쓴다. `rear`를 옮길 위치가 `front`와 같으면 큐가 가득 찬 것으로 보고 예외를 던진다. 표 3의 배치 1(`front = 1`, `rear = 4`)에서 `push(D)`를 하면 `rear`가 5가 되고 D가 [5]에 들어간다.

### 3.5 삭제 연산 (Dequeue)

원소를 삭제할 때는 먼저 `front`를 시계 방향으로 한 칸 옮긴 뒤, `queue[front]`의 원소를 꺼낸다.

```cpp
T pop() {
    if (front == rear)
        throw std::underflow_error("Queue is empty");
    front = (front + 1) % capacity;
    return queue[front];
}
```

`front`는 첫 원소의 한 칸 앞을 가리키므로, `front`를 한 칸 옮긴 위치가 바로 첫 원소이다. 표 3의 배치 1에서 `pop()`을 하면 `front`가 2가 되고 A를 꺼낸다.

## 4. 연결 큐

### 4.1 체인의 두 끝을 배정하는 방법

큐는 체인(연결 리스트)으로 표현할 수 있으며, 큐의 두 끝을 추적하는 변수 `front`와 `rear`가 필요하다. 체인의 두 끝을 큐의 두 끝에 배정하는 방법은 두 가지이다.

1. 체인의 머리(`firstNode`)를 전단으로, 꼬리(`lastNode`)를 후단으로 둔다.
2. 체인의 머리를 후단으로, 꼬리를 전단으로 둔다.

a, b, c, d, e 순서로 넣은 큐를 두 방법으로 나타내면 다음과 같다.

```text
(a) head = front, tail = rear

  front                                         rear
    |                                             |
    v                                             v
  [ a ] ---> [ b ] ---> [ c ] ---> [ d ] ---> [ e ] ---> NULL

(b) head = rear, tail = front

  rear                                          front
    |                                             |
    v                                             v
  [ e ] ---> [ d ] ---> [ c ] ---> [ b ] ---> [ a ] ---> NULL
```

*그림 6. 체인의 머리와 꼬리를 큐의 전단과 후단에 배정하는 두 방법*

두 방법에서 push와 pop의 시간은 다음과 같다.

- **push (후단에 추가):** (a)에서는 `rear`의 다음 노드로 새 노드를 연결하고 `rear`를 옮기면 되고, (b)에서는 새 노드가 현재 `rear`를 가리키게 하고 `rear`를 옮기면 된다. 둘 다 $O(1)$이다.
- **pop (전단에서 삭제):** (a)에서는 `front`를 다음 노드로 옮기면 되므로 $O(1)$이다. (b)에서는 `front` 노드를 지운 뒤 새 전단이 될 앞 노드를 알아야 하는데, 링크가 전단 쪽을 향하므로 `front`에서는 그 노드에 갈 수 없다. `rear`부터 노드 $n$개를 모두 훑어야 하므로 $\Theta(n)$이다.

| 방법 | push (후단) | pop (전단) |
|:-----|:-----|:-----|
| (a) 머리 = 전단, 꼬리 = 후단 | $O(1)$ | $O(1)$ |
| (b) 머리 = 후단, 꼬리 = 전단 | $O(1)$ | $\Theta(n)$ |

*표 7. 체인의 두 끝을 배정하는 두 방법의 시간 복잡도*

따라서 머리를 전단, 꼬리를 후단으로 두는 방법 (a)가 더 낫다.

### 4.2 구현

`front`와 `rear` 포인터를 가진 단일 연결 리스트를 사용한다.
- `enqueue`는 후단에 삽입하며 $O(1)$이다.
- `dequeue`는 전단에서 삭제하며 $O(1)$이다.

```cpp
struct Node {
    T data;
    Node* next;
};
Node* frontNode;
Node* rearNode;
```

다음은 이 구조에서 push와 pop을 구현한 멤버 함수이다(빈 큐는 `frontNode == nullptr`이다).

```cpp
void push(const T& element) {
    Node* p = new Node{element, nullptr};
    if (frontNode == nullptr) frontNode = p;        // empty queue: p is also the front
    else rearNode->next = p;                        // link after the current rear
    rearNode = p;
}

T pop() {
    if (frontNode == nullptr) throw std::underflow_error("Queue is empty");
    Node* p = frontNode;
    T x = p->data;
    frontNode = p->next;                            // the next node becomes the front
    if (frontNode == nullptr) rearNode = nullptr;   // the queue became empty
    delete p;
    return x;
}
```

빈 큐에 push하면 새 노드가 전단이자 후단이 되고, 마지막 원소를 pop하면 `frontNode`와 `rearNode`가 모두 `nullptr`이 된다. 마지막 원소를 pop할 때 `rearNode`를 `nullptr`로 되돌리지 않으면 `rearNode`가 해제된 노드를 가리킨 채 남으므로, 빈 큐를 따로 처리하지 않는 push는 해제된 노드에 새 노드를 연결하게 된다.

### 4.3 장점

- 동적 메모리를 쓰므로 미리 정한 크기 제한이 없다.
- 원형 배열의 한 칸 낭비 방식처럼 칸을 하나 비워 둘 필요가 없어 낭비되는 칸이 없다.

## 5. 양방향 큐 (Deque)

**덱(deque)** 은 양쪽 끝에서 삽입과 삭제가 가능하다:
- `pushFront`, `pushBack`, `popFront`, `popBack` 연산을 제공한다.
- 원형 배열이나 이중 연결 리스트로 구현하면 모든 연산이 $O(1)$이다.

단일 연결 리스트로 구현하면 `popBack`은 새 꼬리가 될 앞 노드를 찾아야 하므로 $O(n)$이다. 덱은 양쪽 끝을 모두 쓸 수 있으므로 스택으로도, 큐로도 사용할 수 있다.

## 6. 큐의 응용

### 6.1 CPU 스케줄링

- 라운드 로빈 스케줄링에서는 프로세스들이 번갈아 가며 CPU를 사용한다. 정해진 시간을 다 쓴 프로세스는 큐의 후단으로 돌아간다.
- 준비 큐(ready queue)는 실행을 기다리는 프로세스를 도착 순서대로 보관한다.

> **[운영체제]** 프로세스는 실행 중인 프로그램이며, 실행할 준비가 되었지만 CPU를 기다리는 프로세스는 준비 큐에 들어간다. 라운드 로빈 스케줄링은 준비 큐의 전단 프로세스에 정해진 시간 할당량(time slice)만큼 CPU를 주고 그 안에 끝나지 않으면 후단으로 보내므로, 큐의 FIFO 순서가 모든 프로세스에 차례대로 CPU를 나눠 준다.

### 6.2 너비 우선 탐색 (BFS)

```text
enqueue(start)
while queue is not empty:
    node = dequeue()
    for each neighbor of node:
        if not visited:
            mark visited
            enqueue(neighbor)
```

큐는 먼저 발견한 정점을 먼저 꺼내므로, 너비 우선 탐색은 시작 정점에서 가까운 정점부터 차례로 방문한다.

> **참고:** 위 의사코드는 시작 정점을 방문했다고 표시하지 않는다. 그래서 시작 정점과 연결된 이웃을 처리할 때 시작 정점이 방문하지 않은 정점으로 보여 큐에 다시 들어갈 수 있다. 시작 정점을 큐에 넣기 전에 방문 표시를 해야 하며, 고친 의사코드는 다음과 같다.

```text
mark start visited
enqueue(start)
while queue is not empty:
    node = dequeue()
    for each neighbor of node:
        if not visited:
            mark visited
            enqueue(neighbor)
```

> **[알고리즘]** 그래프는 정점과 두 정점을 잇는 간선으로 이루어지며, 간선으로 이어진 두 정점을 서로의 이웃이라 한다. 너비 우선 탐색은 기본적인 그래프 알고리즘으로, 큐가 시작 정점에서 간선 수가 적은 정점부터 꺼내 주므로 가중치가 없는 그래프에서 시작 정점으로부터의 최단 경로(간선 수 기준)를 구하는 데 쓰인다.

### 6.3 버퍼 관리

- 인쇄 작업 스풀링은 프린터에 도착한 작업을 도착 순서대로 처리한다.
- 키보드 입력 버퍼는 입력한 순서대로 문자를 프로그램에 전달한다.
- 네트워크 패킷 버퍼링은 도착한 패킷을 처리할 수 있을 때까지 순서대로 보관한다.

## 7. 부록

### 7.1 원형 큐 vs. 선형 큐

| 속성 | 선형 큐 | 원형 큐 |
|------|---------|---------|
| Pop | $O(n)$ 또는 공간 낭비 | $O(1)$ |
| 공간 활용 | 전단에 빈 공간 발생 가능 | 해제된 공간 재사용 |
| 가득 참 감지 | `rear == capacity - 1` | `(rear + 1) % capacity == front` |
| 구현 | 단순 | 나머지 연산 필요 |

*표 8. 선형 큐와 원형 큐의 비교*

### 7.2 큐의 변형

- **우선순위 큐(Priority Queue):** 들어온 순서가 아니라 우선순위에 따라 삭제한다(9강).
- **원형 버퍼(Circular Buffer):** 크기가 고정되어 있으며, 가득 차면 가장 오래된 데이터를 덮어쓴다.
- **메시지 큐(Message Queue):** 프로세스 간 통신에 쓰이는 운영체제의 기법이다.

## 요약

| 개념 | 핵심 요약 |
|------|------------|
| 큐 | 후단에서 삽입하고 전단에서 삭제하는 FIFO 자료구조이다. |
| 단순 배열 큐 | `front`를 0에 고정하므로 pop에 $O(n)$ 이동이 필요하다. |
| 수정된 위치 공식 | `front`가 오른쪽으로 움직여 pop은 $O(1)$이 되지만, 배열 끝에 닿으면 큐를 이동해야 하므로 추가가 최악의 경우 $\Theta(n)$이다. |
| 원형 배열 큐 | 나머지 연산으로 배열을 원형으로 쓰며 모든 연산이 $O(1)$이고, 한 칸 낭비 방식에서는 한 칸을 비워 둔다. |
| 가득 참 vs. 비어 있음 | 둘 다 `front == rear`이므로 한 칸 낭비(capacity - 1개 저장), `lastOperationIsAdd`, 원소 수 카운터 중 하나로 구분한다. |
| 연결 큐 | 체인의 머리를 전단, 꼬리를 후단으로 두어 push와 pop이 모두 $O(1)$인 진정한 동적 구조이다. |
| 덱 | 양쪽 끝에서 삽입과 삭제를 할 수 있는 양방향 큐이다. |

## 점검 문제

1. **수정된 위치 공식:** 크기가 6인 배열(Q(0)\~Q(5))에 수정된 위치 공식을 쓰는 비원형 큐가 있고, `front = 3`, `rear = 5`이다. 원소 수와 $\text{location}(2)$를 구하라. 또 새 원소를 push하려면 무엇이 필요하며, 그 시간은 얼마인가?

   <details>
   <summary>정답</summary>

   원소 수는 `rear - front + 1 = 5 - 3 + 1 = 3`이다. $\text{location}(1) = 3$이므로 $\text{location}(2) = 3 + 2 - 1 = 4$이다. `rear = MaxSize - 1 = 5`이고 `front > 0`이므로 그대로는 추가할 수 없고, 원소 3개를 Q(0)\~Q(2)로 옮겨 `front = 0`, `rear = 2`로 만든 뒤 Q(3)에 넣어야 한다. 이동은 원소 수에 비례하므로 이 push는 $\Theta(n)$이다.

   </details>

2. **`lastOperationIsAdd` 방식:** 용량이 4인 원형 큐가 `front = rear = 0`, `lastOperationIsAdd = false`로 시작한다. `push`를 네 번 한 뒤의 `front`, `rear`, 플래그 값과 큐의 상태를 쓰라. 이어서 `pop`을 네 번 하면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   `push`를 네 번 하면 `rear`가 1, 2, 3, 0으로 움직여 `front = rear = 0`이 되고 플래그는 `true`이다. `front == rear && lastOperationIsAdd`이므로 네 칸이 모두 찬 가득 찬 상태이다. 이어서 `pop`을 네 번 하면 `front`가 1, 2, 3, 0으로 움직여 다시 `front = rear = 0`이 되고 플래그는 `false`이므로 빈 상태이다.

   </details>

3. **저장할 수 있는 원소 수:** 용량이 6인 원형 큐에 한 칸 낭비 방식을 쓸 때와 `NumElements` 방식을 쓸 때 저장할 수 있는 최대 원소 수와 가득 찬 상태의 조건을 각각 쓰라.

   <details>
   <summary>정답</summary>

   한 칸 낭비 방식은 최대 $6 - 1 = 5$개를 저장하며, `(rear + 1) % 6 == front`일 때 가득 찬 것으로 본다. `NumElements` 방식은 여섯 칸을 모두 써서 6개를 저장하며, `NumElements == 6`(즉 `front == rear`이고 `NumElements != 0`)일 때 가득 찬 상태이다. 대신 원소 수 변수를 하나 더 관리해야 한다.

   </details>

4. **연결 큐의 배정:** 체인의 머리를 후단, 꼬리를 전단으로 두면 pop이 $\Theta(n)$인 이유를 설명하라. 이중 연결 리스트를 쓰면 어떻게 달라지는가?

   <details>
   <summary>정답</summary>

   이 배정에서는 링크가 후단에서 전단 쪽을 향하므로, 전단 노드를 지운 뒤 새 전단이 될 앞 노드에 전단 노드에서 갈 수 없다. 그 노드를 찾으려면 후단부터 노드를 모두 훑어야 하므로 $\Theta(n)$이다. 이중 연결 리스트라면 각 노드가 반대 방향 링크도 가지므로 새 전단을 바로 찾아 $O(1)$에 pop할 수 있지만, 노드마다 포인터가 하나 더 필요하다. 단일 연결 리스트에서는 머리를 전단으로 두면 이 문제가 없다.

   </details>

5. **너비 우선 탐색:** 간선이 A-B, A-C, B-D, C-D, D-E인 무방향 그래프에서 A부터 6.2절의 고친 의사코드로 너비 우선 탐색을 한다. 이웃은 알파벳 순서로 처리할 때, 정점이 큐에서 나오는 순서를 쓰라.

   <details>
   <summary>정답</summary>

   A를 표시하고 넣는다(큐: A). A를 꺼내 B, C를 표시하고 넣는다(큐: B, C). B를 꺼내면 A는 이미 방문했으므로 D만 넣는다(큐: C, D). C를 꺼내면 A와 D는 이미 방문했다(큐: D). D를 꺼내 E를 넣는다(큐: E). E를 꺼내면 이웃 D는 이미 방문했다. 따라서 순서는 A, B, C, D, E이다.

   </details>
