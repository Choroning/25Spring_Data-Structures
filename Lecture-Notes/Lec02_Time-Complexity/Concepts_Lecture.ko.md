## 1. 점근적 표기법

### 1.1 동기

정확한 단계 수 계산은 번거롭고 플랫폼에 의존적이다. 점근적 표기법은 함수의 성장률을 기술하는 **기계 독립적인** 방법을 제공한다.

$n \to \infty$일 때 **실행 시간이 어떻게 확장되는지**에 초점을 맞추며, 상수 인자와 저차항은 무시한다.

### 1.2 표기법 개요

| 표기법 | 의미 | 비유 |
|--------|------|------|
| $O(g(n))$ | 상한 | $\leq$ |
| $\Omega(g(n))$ | 하한 | $\geq$ |
| $\Theta(g(n))$ | 엄밀한 한계 | $=$ |
| $o(g(n))$ | 엄격한 상한 | $<$ |
| $\omega(g(n))$ | 엄격한 하한 | $>$ |

*표 1. 점근적 표기법의 종류와 의미*

### 1.3 그래프로 본 의미

세 표기법은 $n_0$ 이후 두 함수의 그래프가 어떤 위치 관계에 있는지로 이해할 수 있다.

| 표기 | $n \ge n_0$에서의 관계 | 의미 |
|------|------|------|
| $f(n) = O(g(n))$ | $f(n)$의 그래프가 $c \cdot g(n)$의 아래에 있다 | $f(n)$은 $g(n)$보다 빠르게 증가하지 않는다 |
| $f(n) = \Omega(g(n))$ | $f(n)$의 그래프가 $c \cdot g(n)$의 위에 있다 | $f(n)$은 $g(n)$보다 느리게 증가하지 않는다 |
| $f(n) = \Theta(g(n))$ | $f(n)$의 그래프가 $c_1 \cdot g(n)$과 $c_2 \cdot g(n)$ 사이에 있다 | $f(n)$은 점근적으로 $g(n)$과 같은 비율로 증가한다 |

*표 2. 그래프로 본 세 표기법의 관계*

이 표기에서 $f(n)$은 분석 대상인 함수(예: 알고리즘의 실행 시간)이고, $g(n)$은 $f(n)$을 한정하는 기준 함수이다. 예를 들어 $f(n)$이 알고리즘의 실행 시간이고 $g(n)$이 어떤 시간 복잡도 함수일 때, $n_0$ 이후의 모든 입력 크기 $n$에서 $f(n)$이 $c \cdot g(n)$ 이하이면 $f(n)$은 $O(g(n))$이다. 점근적 표기법은 입력 크기가 커질 때의 행동을 보고 알고리즘의 실행 시간을 분석한다.

> **참고:** **집합 표기.** $O(g(n))$은 함수의 집합이므로 $f(n) = O(g(n))$을 $f(n) \in O(g(n))$으로도 쓴다. 이때 등호는 대칭 관계가 아니라 소속을 뜻하므로 $O(g(n)) = f(n)$처럼 거꾸로 쓰지 않는다. 문헌에 따라 분석 대상을 $g(n)$, 기준 함수를 $f(n)$으로 바꾸어 $g(n) \in O(f(n))$으로 쓰기도 하므로 어느 쪽이 기준 함수인지 확인해야 한다.

## 2. Big-O 표기법

### 2.1 정의

양의 상수 $c$와 $n_0$이 존재하여 다음을 만족하면 $f(n) = O(g(n))$이다("f(n)은 g(n)의 Big-O"라고 읽는다):

$$f(n) \leq c \cdot g(n) \quad \text{for all } n \geq n_0$$

Big-O는 성장률에 대한 **점근적 상한**을 제공한다. $f(n)$은 평가 대상 알고리즘의 복잡도이고 $g(n)$은 비교 기준이 되는 복잡도이다. 어떤 알고리즘의 시간 복잡도가 $O(g(n))$이면, 충분히 큰 입력 크기 $n$에서 이 알고리즘의 수행 시간은 상수배를 제외하면 아무리 늦어도 $g(n)$을 넘지 않는다. 곧 $g(n)$이 상한이다.

예를 들어 $f(n) = O(n^2)$은 $f(n)$이 궁극적으로(어떤 $n_0$보다 큰 모든 $n$에서) 어떤 이차 함수 $cn^2$보다 작거나 같은 값을 가진다는 뜻이다. 그래프에서는 $f(n)$이 $cn^2$의 아래에 놓이며, $f(n)$이 궁극적으로 $cn^2$보다 나쁘지 않다(빠르게 증가하지 않는다)고 말할 수 있다.

### 2.2 예시

- $3n + 2 = O(n)$: $n \geq 2$일 때 $3n + 2 \leq 4n$ ($c = 4$, $n_0 = 2$ 선택)
- $10n^2 + 4n + 2 = O(n^2)$: $n \geq 5$일 때 $10n^2 + 4n + 2 \leq 11n^2$
- $6 \cdot 2^n + n^2 = O(2^n)$: 충분히 큰 $n$에 대해 $6 \cdot 2^n + n^2 \leq 7 \cdot 2^n$ ($n \ge 4$에서 $n^2 \le 2^n$이므로 $n_0 = 4$)

**$n^2 + 10n = O(n^2)$.** $n \ge 10$인 모든 정수 $n$에서 $10n \le n^2$이므로 $n^2 + 10n \le 2n^2$이 성립한다. 따라서 $c = 2$, $n_0 = 10$을 선택하면 Big-O의 정의에 의해 $n^2 + 10n = O(n^2)$이다. 또 $n \ge 1$인 모든 정수 $n$에서 $10n \le 10n^2$이므로 $n^2 + 10n \le 11n^2$이 성립하고, $c = 11$, $n_0 = 1$을 선택해도 같은 결론을 얻는다. 이처럼 정의를 만족하는 $c$와 $n_0$은 하나로 정해지지 않는다.

| $n$ | 1 | 5 | 9 | 10 | 11 | 15 |
|---|---|---|---|---|---|---|
| $n^2 + 10n$ | 11 | 75 | 171 | 200 | 231 | 375 |
| $2n^2$ | 2 | 50 | 162 | 200 | 242 | 450 |

*표 3. $n^2 + 10n$과 $2n^2$의 값 비교*

$n < 10$에서는 $n^2 + 10n$이 더 크지만, $n = 10$에서 두 값이 같아지고 그 뒤로는 $n^2 + 10n$이 $2n^2$ 아래에 머문다.

다음도 정의로 확인할 수 있다.

- $5n^2 = O(n^2)$: $c = 5$로 잡으면 모든 $n \ge 1$에서 $5n^2 \le 5n^2$이다(실제로는 모든 $n \ge 0$에서 성립한다).
- $T(n) = \dfrac{n(n-1)}{2} = O(n^2)$: 모든 $n \ge 0$에서 $\dfrac{n(n-1)}{2} \le \dfrac{n^2}{2}$이므로 $c = \dfrac{1}{2}$, $n_0 = 1$로 잡으면 된다.
- $n^2 = O(n^2 + 10n)$: 모든 $n \ge 0$에서 $n^2 \le 1 \cdot (n^2 + 10n)$이므로 $c = 1$, $n_0 = 1$로 잡으면 된다.
- $n = O(n^2)$: $n \ge 1$인 모든 정수 $n$에서 $n \le 1 \cdot n^2$이므로 $c = 1$, $n_0 = 1$로 잡으면 된다.

### 2.3 Big-O가 성립하지 않는 예

$n^3 \ne O(n^2)$이다. $n \ge n_0$인 모든 $n$에서 $n^3 \le c \cdot n^2$을 만족하는 $c$와 $n_0$이 있다고 가정한다. 양변을 $n^2$으로 나누면 $n \le c$가 되는데, $c$를 아무리 크게 잡아도 $n_0$ 이상이면서 $c$보다 큰 $n$이 존재한다. 따라서 그런 $c$와 $n_0$은 존재하지 않는다.

> **주의:** 작은 $n$에서는 부등식이 우연히 성립할 수 있다. $c = 5$로 고정하면 $n = 2$에서는 $2^3 = 8 \le 5 \times 2^2 = 20$으로 참이지만, $n = 10$에서는 $10^3 = 1000 \le 5 \times 10^2 = 500$은 거짓이다. Big-O는 $n_0$ 이후의 모든 $n$에서 성립해야 하므로 몇 개의 값을 시험해서는 증명할 수 없다. $n \le c$ 꼴에서는 어떤 $c$를 고르든 $c$보다 큰 $n$을 골라 부등식을 깰 수 있으므로 관계는 항상 거짓이다.

### 2.4 성질

1. **추이성**: $f = O(g)$이고 $g = O(h)$이면, $f = O(h)$
2. **합의 규칙**: $O(f + g) = O(\max(f, g))$
3. **곱의 규칙**: $O(f \cdot g) = O(f) \cdot O(g)$
4. **상수 인자**: 임의의 상수 $c > 0$에 대해 $O(c \cdot f) = O(f)$

> **핵심:** Big-O는 함수의 *상한*을 기술한다. 함수가 $g(n)$보다 *빠르게 증가하지 않음*을 의미한다. 최악 경우 실행 시간을 나타낼 때 자주 쓰지만, 최선 경우나 평균 경우의 함수에도 똑같이 쓸 수 있다.

## 3. Big-Omega 표기법

### 3.1 정의

양의 상수 $c$와 $n_0$이 존재하여 다음을 만족하면 $f(n) = \Omega(g(n))$이다:

$$f(n) \geq c \cdot g(n) \quad \text{for all } n \geq n_0$$

### 3.2 예시

- $3n + 2 = \Omega(n)$: $n \geq 1$일 때 $3n + 2 \geq 3n$
- $n^2 - 5n = \Omega(n^2)$: $n \geq 10$일 때 $n^2 - 5n \geq \frac{1}{2}n^2$

> **핵심:** Big-Omega는 *하한*을 제공한다. 함수가 *최소한 $g(n)$만큼 빠르게* 증가한다는 의미이다.

## 4. Theta 표기법

### 4.1 정의

양의 상수 $c_1$, $c_2$, $n_0$이 존재하여 다음을 만족하면 $f(n) = \Theta(g(n))$이다:

$$c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n) \quad \text{for all } n \geq n_0$$

동치 조건으로, $f(n) = O(g(n))$ **이고** $f(n) = \Omega(g(n))$이면 $f(n) = \Theta(g(n))$이다.

### 4.2 예시

- $3n + 2 = \Theta(n)$: $n \geq 2$일 때 $3n \leq 3n+2 \leq 4n$
- $n^2 / 2 - 3n = \Theta(n^2)$: $n \ge 12$일 때 $\frac{1}{4}n^2 \le n^2/2 - 3n \le \frac{1}{2}n^2$ ($c_1 = 1/4$, $c_2 = 1/2$, $n_0 = 12$)

### 4.3 O, Omega, Theta의 관계

$O(n^2)$, $\Omega(n^2)$, $\Theta(n^2)$은 각각 함수의 집합이다. 다음 표는 몇 가지 함수가 어느 집합에 속하는지 보여 준다.

| 함수 | $O(n^2)$ | $\Omega(n^2)$ | $\Theta(n^2)$ |
|------|------|------|------|
| $3\lg n + 8$ | 예 | 아니오 | 아니오 |
| $5n + 7$ | 예 | 아니오 | 아니오 |
| $2n \lg n$ | 예 | 아니오 | 아니오 |
| $4n^2$ | 예 | 예 | 예 |
| $6n^2 + 9$ | 예 | 예 | 예 |
| $5n^2 + 2n$ | 예 | 예 | 예 |
| $4n^3 + 3n^2$ | 아니오 | 예 | 아니오 |
| $6n^6 + n^4$ | 아니오 | 예 | 아니오 |
| $2^n + 4n$ | 아니오 | 예 | 아니오 |

*표 4. 예시 함수의 $O(n^2)$, $\Omega(n^2)$, $\Theta(n^2)$ 소속*

$\Theta(n^2) = O(n^2) \cap \Omega(n^2)$이다. $\Theta(n^2)$에 속하는 $4n^2$, $6n^2 + 9$, $5n^2 + 2n$은 상한과 하한이 같은 차수 $n^2$이며, 이 한계는 더 좁힐 수 없다.

> **주의:** 실행 시간이 $\Theta(g(n))$이라는 것은 그 알고리즘의 상한과 하한이 같은 차수라는 뜻일 뿐, 알고리즘이 최적이라는 뜻은 아니다. 알고리즘이 최적이려면 그 상한이 문제 자체의 하한과 같아야 한다(1강 4.4절). 예를 들어 버블 정렬의 비교 횟수 $n(n-1)/2$는 $\Theta(n^2)$이지만, 비교 기반 정렬 문제의 하한은 $\Omega(n \log n)$이므로 버블 정렬은 최적이 아니다.

## 5. Little-o와 Little-omega

### 5.1 Little-o

$f(n) = o(g(n))$은 $\lim_{n \to \infty} \frac{f(n)}{g(n)} = 0$을 의미한다.

예시: $n = o(n^2)$, $\log n = o(n)$

부등식으로 쓰면, **모든** 양의 상수 $c$에 대해 각각 $n_0$이 존재하여 $n \ge n_0$인 모든 $n$에서 $f(n) \le c \cdot g(n)$일 때 $f(n) = o(g(n))$이다($g(n)$이 충분히 큰 $n$에서 양수이면 극한을 이용한 정의와 같다). Big-O와 little-o의 차이는 다음과 같다.

1. **Big-O**: 부등식을 만족하는 양의 실수 $c$가 **하나라도** 있으면 참이다.
2. **Little-o**: 부등식이 **모든** 양의 실수 $c$에 대해 만족되어야 참이다.

$f(n) = o(g(n))$이면 $f(n)$의 성능은 $g(n)$보다 훨씬 좋다(증가가 훨씬 느리다).

### 5.2 Little-omega

$f(n) = \omega(g(n))$은 $\lim_{n \to \infty} \frac{f(n)}{g(n)} = \infty$를 의미한다.

예시: $n^2 = \omega(n)$

## 6. 복잡도 차수의 성질

다음 성질은 함수 사이의 차수를 비교할 때 쓴다. "A iff B"(A if and only if B)는 A와 B가 서로 필요충분조건이라는 뜻으로, 두 방향이 모두 성립한다. 반면 "A if B"는 B가 참이면 A가 참이라는 뜻일 뿐, A가 참일 때 B는 참일 수도 거짓일 수도 있다.

- **쌍대성:** $f(n) = O(g(n))$ iff $g(n) = \Omega(f(n))$이다.
- **대칭성:** $f(n) = \Theta(g(n))$ iff $g(n) = \Theta(f(n))$이다.
- **로그 함수:** $a > 1$, $b > 1$이면 $\log_a n = \Theta(\log_b n)$이 항상 성립한다. 모든 로그 복잡도 함수는 같은 클래스에 속하므로 보통 밑을 생략하고 $\Theta(\log n)$으로 쓴다.
- **지수 함수:** $b > a > 0$이면 $a^n = o(b^n)$이다. 로그 함수와 달리 지수 복잡도 함수는 모두 같은 클래스에 속하지 않는다.
- **계승:** $a > 0$이면 $a^n = o(n!)$이다. 곧 $n!$은 어떤 지수 시간 복잡도 함수보다도 나쁘다.

복잡도 클래스를 좋은 것부터 나쁜 것 순서로 나열하면 다음과 같다($k > j > 2$, $b > a > 1$).

$$\Theta(\lg n),\ \Theta(n),\ \Theta(n \lg n),\ \Theta(n^2),\ \Theta(n^j),\ \Theta(n^k),\ \Theta(a^n),\ \Theta(b^n),\ \Theta(n!)$$

복잡도 함수 $f(n)$의 클래스가 $g(n)$의 클래스보다 왼쪽에 있으면 $f(n) = o(g(n))$이다.

**합의 성질.** $f(n) = O(h(n))$, $g(n) = \Theta(h(n))$이고 $c > 0$, $d > 0$이면 $c \cdot f(n) + d \cdot g(n) = \Theta(h(n))$이다. 곧 여러 항을 더하면 가장 높은 차수의 항이 클래스를 결정하며, 차수가 같거나 낮은 항을 더하거나 양의 상수 계수를 곱해도 클래스는 바뀌지 않는다. 예를 들어 $3\lg n + 5n^2 = \Theta(n^2)$이다.

$2^n$과 $10^n$ 같은 지수 함수는 $\log n$, $n$, $n \log n$, $n^2$, $n^3$보다 훨씬 가파르게 증가한다. 예를 들어 $n = 11$에서 $n^3 = 1331$이지만 $2^n = 2048$이고 $10^n = 10^{11}$이다.

## 7. 극한을 이용한 차수 비교

### 7.1 로피탈 정리와 극한 판정

**로피탈 정리(L'Hôpital's rule):** $\lim_{n \to \infty} f(n) = \lim_{n \to \infty} g(n) = \infty$이고 우변의 극한이 존재하면 다음이 성립한다.

$$\lim_{n \to \infty} \frac{f(n)}{g(n)} = \lim_{n \to \infty} \frac{f'(n)}{g'(n)}$$

> **[미적분학]** 로피탈 정리는 $\infty/\infty$나 $0/0$ 꼴인 부정형의 극한을 분자와 분모의 도함수의 비로 구하는 미적분학의 정리이다. 복잡도 함수는 정수 $n$에서 정의되지만 $n^2$, $\lg n$, $2^n$처럼 실수 $x$에서 미분 가능한 함수로 확장하여 정리를 적용하며, $x \to \infty$일 때의 극한이 존재하면 정수 $n \to \infty$일 때의 극한도 그 값과 같다.

이 정리는 복잡도 차수를 비교할 때 매우 중요하다. 두 함수의 비의 극한을 구하면 다음과 같이 관계를 판정할 수 있다.

| $\lim_{n \to \infty} f(n)/g(n)$ | 결론 |
|------|------|
| $0$ | $f(n) = o(g(n))$ (따라서 $f(n) = O(g(n))$이지만 $f(n) \ne \Theta(g(n))$) |
| $0 < c < \infty$인 상수 $c$ | $f(n) = \Theta(g(n))$ |
| $\infty$ | $f(n) = \omega(g(n))$ (따라서 $f(n) = \Omega(g(n))$이지만 $f(n) \ne \Theta(g(n))$) |

*표 5. 극한값에 따른 점근 관계 판정*

> **주의:** 극한 판정은 극한값에서 관계를 이끌어 내는 방향으로만 쓴다. $f(n) = O(g(n))$이라고 해서 $\lim f(n)/g(n) = 0$인 것은 아니며($f = g$이면 극한은 1이다), 극한이 존재하지 않아도 관계는 성립할 수 있다. 예를 들어 짝수 $n$에서 $n$, 홀수 $n$에서 $2n$인 함수는 $f(n)/n$이 1과 2를 오가므로 극한이 없지만 $n \le f(n) \le 2n$이므로 $\Theta(n)$이다.

### 7.2 증명 예제

**$\dfrac{n^2}{2} = o(n^3)$:**

$$\lim_{n \to \infty} \frac{n^2/2}{n^3} = \lim_{n \to \infty} \frac{1}{2n} = 0$$

**$b > a > 0$이면 $a^n = o(b^n)$:** $0 < a/b < 1$이므로

$$\lim_{n \to \infty} \frac{a^n}{b^n} = \lim_{n \to \infty} \left(\frac{a}{b}\right)^n = 0$$

**$\lg n = o(n)$:** 로피탈 정리를 적용한다($\lg n = \log_2 n$이고 $(\lg n)' = \frac{1}{n \ln 2}$).

$$\lim_{n \to \infty} \frac{\lg n}{n} = \lim_{n \to \infty} \frac{1/(n \ln 2)}{1} = 0$$

**$a > 1$, $b > 1$이면 $\log_a n = \Theta(\log_b n)$:** $(\log_a f(n))' = \dfrac{f'(n)}{f(n) \ln a}$이므로

$$\lim_{n \to \infty} \frac{\log_a n}{\log_b n} = \lim_{n \to \infty} \frac{1/(n \ln a)}{1/(n \ln b)} = \frac{\ln b}{\ln a} = \frac{\log b}{\log a} > 0$$

극한이 양의 상수이므로 두 함수는 같은 클래스에 속한다. 밑 변환 공식 $\log_a n = \log_b n / \log_b a$로도 두 함수의 비가 상수임을 바로 알 수 있다.

**$f(n) = \log n^2$, $g(n) = \log n + 5$:** 로피탈 정리를 적용하면

$$\lim_{n \to \infty} \frac{\log n^2}{\log n + 5} = \lim_{n \to \infty} \frac{2/n}{1/n} = 2$$

이고 $0 < 2 < \infty$이므로 $f(n) = \Theta(g(n))$이다. 여기서 $\log n + 5$는 $\log(n + 5)$와 다르다는 데 주의한다. $\log n^2 = 2\log n$이므로 같은 결론을 바로 얻을 수도 있다.


## 9. 반복문의 복잡도 분석

### 9.1 단계 수에서 점근 복잡도로

다음 함수는 $N$개의 정수를 담은 배열 `A`의 모든 수의 합을 구한다.

```cpp
// 입력: int A[N], N개의 정수 배열
// 출력: 배열 A의 모든 수의 합
int Sum(int A[], int N) {
    int s = 0;                      // (1)
    for (int i = 0; i < N; i++)     // (2) i = 0, (3) i < N, (4) i++
        s = s + A[i];               // (5) 대입, (6) 덧셈, (7) A[i] 접근
    return s;                       // (8)
}
```

(1), (2), (8)은 한 번씩 실행되고, (3)부터 (7)까지는 반복마다 한 번씩 $N$번 실행된다고 세면 총 단계 수는 $5N + 3$이다. 이 알고리즘의 **복잡도 함수(complexity function)** 는 $f(N) = 5N + 3$이다.

| $N$ | 단계 수 |
|---|---|
| 10 | 53 |
| 100 | 503 |
| 1,000 | 5,003 |
| 1,000,000 | 5,000,003 |

*표 7. N에 따른 Sum 함수의 단계 수*

$N$이 커지면 이 함수의 단계 수는 $N$에 선형으로 비례하여 증가한다.

> **참고:** **마지막 검사의 계수.** 엄밀히는 (3)의 검사 `i < N`이 조건이 거짓이 되는 마지막 검사까지 $N+1$번 실행되므로 총 단계 수는 $5N + 4$이다. 결론(선형 증가)은 같다.

$5N + 3$의 $+3$과 계수 5는 다음 이유로 중요하지 않다.

- $N$이 커지면 $+3$은 무의미해진다.
- 연산마다 걸리는 시간이 달라 계수 5는 정확하지 않으며, 중요한 의미도 없다.

근본적인 사실은 시간이 $N$에 **선형**이라는 점이다. **점근 복잡도**는 $N$이 커질 때 최고차항에 집중한다. 곧 $+3$ 같은 저차항을 버리고, 최고차항의 상수 계수를 버린다. 이렇게 하면 $5N + 3$의 시간 한계는 $N$처럼 **점근적으로 증가한다(grow asymptotically)** 고 말한다. **점근적(asymptotic)** 이란 변수가 극한(보통 무한대)에 가까워질 때 식이 점점 정확해지는 성질을 말한다. 점근 복잡도는 알고리즘 복잡도의 근사치를 주며, 기계에 의존하는 많은 세부 사항을 무시하고 큰 그림에 집중하게 한다.

### 9.2 단일 반복문

반복문은 두 부분으로 나누어 분석한다. 반복이 몇 번 수행되는가? 반복마다 몇 단계가 수행되는가? 반복문의 복잡도는 반복 횟수와 본문의 복잡도를 곱한 값이다.

```cpp
int sum = 0, j;
for (j = 0; j < N; j++)
    sum = sum + j;
```

반복은 $N$번($j = 0, \ldots, N-1$) 수행되고, 반복마다 4단계(검사, 덧셈, 대입, 증가)가 수행되며, 반복 전의 초기화 `sum = 0`과 `j = 0`이 2단계이므로 총 $4N + 2$단계이다. 계수 4는 상수이므로 $4 = O(1)$로 무시할 수 있고, 총 시간은 $N \cdot O(1) = O(N \cdot 1) = O(N)$이다.

```cpp
int sum = 0, j;
for (j = 0; j < 100; j++)
    sum = sum + j;
```

이 반복문은 $N$과 관계없이 100번 실행되고 반복마다 $4 = O(1)$단계이므로 총 시간은 $100 \cdot O(1) = O(100 \cdot 1) = O(100) = O(1)$이다.

### 9.3 중첩 반복문

중첩 반복문은 단일 반복문처럼 다루되, 필요한 만큼 각 단계의 중첩을 평가한다.

```cpp
int j, k;
for (j = 0; j < N; j++)
    for (k = N; k > 0; k--)
        sum += k + j;
```

바깥 반복문부터 분석한다. 바깥 반복은 $N$번 수행되고, 반복마다 걸리는 시간은 안쪽 반복문을 평가해야 알 수 있다. 안쪽 반복문은 $O(N)$ 시간이 걸리므로 총 시간은 $N \cdot O(N) = O(N \cdot N) = O(N^2)$이다.

한 반복문의 반복 횟수가 다른 반복문의 카운터에 의존하면 두 반복문을 함께 분석한다.

```cpp
int j, k;
for (j = 0; j < N; j++)
    for (k = 0; k < j; k++)
        sum += k + j;   // sum = sum + (k + j)
```

안쪽 반복은 $j$번 수행되므로 안쪽 반복의 총 횟수는 다음과 같다.

$$0 + 1 + 2 + \cdots + (N-1) = \frac{N(N-1)}{2} = O(N^2)$$

### 9.4 문장의 나열

문장이 차례로 나열되어 있으면 각 문장의 복잡도 함수를 따로 구해 더한다.

```cpp
for (j = 0; j < N; j++)
    for (k = 0; k < j; k++)
        sum = sum + j * k;
for (l = 0; l < N; l++)
    sum = sum - l;
cout << "sum is now " << sum;
```

첫 번째 이중 반복문은 $O(N^2)$, 두 번째 반복문은 $O(N)$, 마지막 출력문은 $O(1)$이다. 따라서 이 프로그램의 시간 복잡도의 상한(최악 경우)은 $O(N^2) + O(N) + O(1) = O(N^2)$이다.

### 9.5 반복문의 종류별 예

`for`, `while`, `do-while` 반복문의 복잡도는 반복 횟수에 본문의 복잡도를 곱하여 결정된다.

| 코드 | 복잡도 |
|------|--------|
| `for (int i = 0; i < n; i++) sum = sum - i;` | $O(n)$ |
| `for (int i = 0; i < n * n; i++) sum = sum + i;` | $O(n^2)$ |
| `i = 1; while (i < n) { sum = sum + i; i = i * 2; }` | $O(\log n)$ |
| `for (int i = 0; i < 100000; i++) sum = sum + i;` | $O(1)$ |

*표 8. 반복문의 종류별 복잡도*

`while` 반복문에서 `i`는 매번 두 배가 된다. $n$에 따라 반복 횟수를 세면 다음과 같다.

| $n$ | 검사한 `i` 값 | 반복 횟수 |
|---|---|---|
| 2 | 1 (1 < 2 참), 2 (2 < 2 거짓) | 1 |
| 4 | 1, 2 (참), 4 (4 < 4 거짓) | 2 |
| 8 | 1, 2, 4 (참), 8 (8 < 8 거짓) | 3 |
| 16 | 1, 2, 4, 8 (참), 16 (16 < 16 거짓) | 4 |

*표 9. 두 배씩 커지는 while 반복문의 반복 횟수*

`i`는 $1, 2, 2^2, 2^3, \ldots$로 커지므로 $n = 2^k$이면 $k = \log_2 n$번 반복한다. 일반적인 $n \ge 1$에서 반복 횟수는 $\lceil \log_2 n \rceil$이다.

## 10. 복잡도 분석 기법

### 10.1 점화식

많은 재귀 알고리즘의 시간 복잡도는 점화식으로 기술된다:

$$T(n) = aT(n/b) + f(n)$$

**마스터 정리(Master Theorem)**: 상수 $a \ge 1$, $b > 1$, $d \ge 0$에 대해 $T(n) = aT(n/b) + \Theta(n^d)$가 주어질 때:

1. $d < \log_b a$이면: $T(n) = \Theta(n^{\log_b a})$
2. $d = \log_b a$이면: $T(n) = \Theta(n^d \log n)$
3. $d > \log_b a$이면: $T(n) = \Theta(n^d)$

> **[알고리즘]** 점화식 $T(n) = aT(n/b) + f(n)$은 크기 $n$인 문제를 크기 $n/b$인 부분 문제 $a$개로 나누어 재귀적으로 풀고 나누기와 합치기에 $f(n)$ 시간을 쓰는 분할 정복 알고리즘의 실행 시간이다. $f(n) = \Theta(n^d)$이면 재귀 트리의 깊이 $i$에 드는 비용은 대략 $a^i (n/b^i)^d = n^d (a/b^d)^i$이므로, 깊어질수록 비용이 커지면($d < \log_b a$) 리프 쪽이, 깊이마다 같으면($d = \log_b a$) $\log_b n$개 레벨 전체가, 작아지면($d > \log_b a$) 루트가 전체 비용을 결정하여 마스터 정리의 세 경우가 된다.

### 10.2 예시

**병합 정렬(Merge Sort)**: $T(n) = 2T(n/2) + \Theta(n)$
- $a = 2$, $b = 2$, $d = 1$
- $\log_2 2 = 1 = d$ (경우 2)
- $T(n) = \Theta(n \log n)$

**이진 검색(Binary Search)**: $T(n) = T(n/2) + \Theta(1)$
- $a = 1$, $b = 2$, $d = 0$
- $\log_2 1 = 0 = d$ (경우 2)
- $T(n) = \Theta(\log n)$

### 10.3 분할 상환 분석

일부 연산은 가끔 비용이 크지만 연산 여러 번에 걸쳐 평균을 내면 저렴하다. **분할 상환 분석(Amortized Analysis)** 은 연산 수열에 대한 연산당 평균 비용을 제공한다. 이 평균은 입력의 확률 분포를 가정하는 평균 경우 분석(1강 3.5절)과 달리 최악의 연산 수열에서도 성립한다.

예시: 동적 배열 `push_back`(3강 2.6절):
- 일반적으로 $O(1)$ (단순 추가)
- 가끔 $O(n)$ (가득 찬 배열을 두 배 크기의 새 배열로 복사할 때)
- 분할 상환 비용: 연산당 $O(1)$

### 11.2 정렬 알고리즘 복잡도 비교

| 알고리즘 | 최선 | 평균 | 최악 | 공간 |
|----------|------|------|------|------|
| 버블 정렬 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ |
| 삽입 정렬 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ |
| 병합 정렬 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ |
| 퀵 정렬 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ |
| 힙 정렬 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ |

*표 10. 정렬 알고리즘의 시간 복잡도와 공간 복잡도*

버블 정렬의 최선 경우 $O(n)$은 한 번 훑는 동안 교환이 없으면 멈추는 구현을 가정한다. 퀵 정렬의 공간 $O(\log n)$은 평균 재귀 깊이이며, 두 부분 중 더 작은 쪽을 먼저 재귀 호출하고 큰 쪽은 반복으로 처리하면 최악 경우에도 $O(\log n)$으로 유지할 수 있다.

## 요약

| 개념 | 핵심 요약 |
|------|------------|
| Big-O | 큰 $n$에 대해 $f(n) \leq c \cdot g(n)$을 만족하는 상한이다. |
| Big-Omega | 큰 $n$에 대해 $f(n) \geq c \cdot g(n)$을 만족하는 하한이다. |
| Theta | $O$와 $\Omega$를 모두 만족하는 엄밀한 한계이며, $\Theta(g) = O(g) \cap \Omega(g)$이다. |
| Little-o | 모든 양의 상수 $c$에 대해 상한이 성립하는 엄격한 상한이며, $\lim f/g = 0$과 같다. |
| 성장률 계층 | $1 < \log n < n < n\log n < n^2 < 2^n < n!$ 순서로 증가가 빨라진다. |
| 극한 판정 | $\lim f/g$가 0이면 $o$, 양의 상수이면 $\Theta$, 무한대이면 $\omega$이며, 로피탈 정리로 극한을 구한다. |
| 반복문 분석 | 반복 횟수와 본문 복잡도를 곱하고, 나열된 문장의 복잡도는 더한 뒤 최고차항만 남긴다. |
| 마스터 정리 | $T(n) = aT(n/b) + \Theta(n^d)$ 꼴의 점화식을 $d$와 $\log_b a$의 비교로 해결한다. |
| 분할 상환 분석 | 연산 수열 전체에 대한 연산당 평균 비용을 구한다. |

## 점검 문제

1. **극한 판정:** $f(n) = 3n^2 + 5n$, $g(n) = n^2$일 때 극한을 이용하여 두 함수의 점근 관계를 판정하라.

   <details>
   <summary>정답</summary>

   $\lim_{n \to \infty} (3n^2 + 5n)/n^2 = \lim_{n \to \infty} (3 + 5/n) = 3$이다. 극한이 $0 < 3 < \infty$인 상수이므로 $f(n) = \Theta(g(n))$, 곧 $3n^2 + 5n = \Theta(n^2)$이다.

   </details>

2. **로그의 밑:** $\log_2 n$과 $\log_{10} n$은 같은 복잡도 클래스에 속하는가?

   <details>
   <summary>정답</summary>

   속한다. 밑 변환 공식에 따라 $\log_2 n / \log_{10} n = \log_2 10 \approx 3.32$로 $n$과 관계없는 양의 상수이므로 $\log_2 n = \Theta(\log_{10} n)$이다. 그래서 복잡도에서는 로그의 밑을 생략하고 $\Theta(\log n)$으로 쓴다.

   </details>

3. **지수 함수의 비교:** $2^n = \Theta(3^n)$인가?

   <details>
   <summary>정답</summary>

   아니다. $\lim_{n \to \infty} 2^n / 3^n = \lim_{n \to \infty} (2/3)^n = 0$이므로 $2^n = o(3^n)$이다. $2^n = O(3^n)$은 성립하지만 $2^n = \Omega(3^n)$은 성립하지 않으므로 $\Theta$ 관계가 아니다. 로그 함수와 달리 밑이 다른 지수 함수는 서로 다른 클래스에 속한다.

   </details>

4. **문장의 나열:** 다음 코드에서 `sum++`가 실행되는 횟수와 시간 복잡도를 구하라.

   ```cpp
   for (int i = 0; i < n; i++)
       for (int j = 0; j < 10; j++)
           sum++;
   for (int k = 1; k < n; k *= 2)
       sum++;
   ```

   <details>
   <summary>정답</summary>

   첫 번째 이중 반복문은 안쪽 반복이 $n$과 관계없이 10번이므로 $10n$번 실행되어 $O(n)$이다. 두 번째 반복문은 `k`가 두 배씩 커지므로 $\lceil \log_2 n \rceil$번 실행되어 $O(\log n)$이다. 총 $10n + \lceil \log_2 n \rceil$번이며(예: $n = 100$이면 1007번), 시간 복잡도는 $O(n) + O(\log n) = O(n)$이다.

   </details>

5. **Theta와 최적성:** 어떤 비교 기반 정렬 알고리즘의 최악 경우 실행 시간이 $\Theta(n^2)$이면 그 알고리즘은 최적인가?

   <details>
   <summary>정답</summary>

   최적이 아니다. $\Theta(n^2)$은 그 알고리즘의 실행 시간이 정확히 이차로 증가한다는 뜻일 뿐이다. 비교 기반 정렬 문제의 하한은 $\Omega(n \log n)$이고 힙 정렬이 $O(n \log n)$으로 이 하한을 달성하므로, 최악 경우 $\Theta(n^2)$인 알고리즘은 최적이 아니다.

   </details>
