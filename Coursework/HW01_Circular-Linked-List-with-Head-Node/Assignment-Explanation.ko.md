## 2. 요구사항

### 2.1 리스트의 구조

노드는 데이터 필드 `data`와 링크 필드 `link`를 가진 `ChainNode<T>`이다. 리스트는 데이터를 담지 않는 **헤드 노드(head node)** 를 하나 두고, 포인터 `head`가 언제나 헤드 노드를 가리킨다. 헤드 노드의 링크는 첫 데이터 노드를 가리키고, 마지막 데이터 노드의 링크는 `NULL`이 아니라 헤드 노드를 가리킨다. 데이터 노드가 하나도 없는 빈 리스트는 헤드 노드의 링크가 헤드 노드 자신을 가리키는 상태이다. 3강 6.3절의 그림 9와 같은 구조이며, 3강의 포인터 `first`가 이 과제의 `head`에 해당한다.

```text
데이터 노드가 6개인 리스트 (3, 2, 1, 2, 4, 6)
head --> [H] --> [3] --> [2] --> [1] --> [2] --> [4] --> [6] --+
          ^                                                    |
          +----------------------------------------------------+

빈 리스트
head --> [H] --+
          ^    |
          +----+
```

*그림 2. 헤드 노드가 있는 원형 연결 리스트와 빈 리스트 (H는 헤드 노드)*

## 3. 설계와 해결 방법

### 3.1 InsertFront

맨 앞에 삽입한다는 것은 헤드 노드와 첫 데이터 노드 사이에 새 노드를 끼워 넣는다는 뜻이다. 풀이는 두 문장으로 이를 처리한다.

```cpp
newNode->link = head->link;   // (1-1) 새 노드가 원래의 첫 노드를 가리킨다
head->link = newNode;         // (1-2) 헤드 노드가 새 노드를 가리킨다
```

두 문장의 순서가 중요하다. (1-2)를 먼저 실행하면 원래의 첫 노드 주소가 담긴 `head->link`를 덮어쓰므로, 그 뒤의 (1-1)은 새 노드가 자기 자신을 가리키게 만들고 원래의 데이터 노드들에는 더 이상 도달할 수 없다. 빈 리스트에서는 `head->link`가 `head`이므로 (1-1)이 새 노드의 링크를 헤드 노드로 정하고, (1-2) 뒤에는 헤드 노드와 새 노드가 하나의 원을 이룬다. 따라서 빈 리스트를 따로 검사하지 않아도 되고, 마지막 노드의 링크도 바꿀 필요가 없다. 마지막 노드는 첫 데이터 노드가 아니라 헤드 노드를 가리키기 때문이다. 시간 복잡도는 $O(1)$이다.

```text
삽입 전          head --> [H] --> [2] --> [1] --> (H로 돌아감)
(1-1) 뒤                [3] ----> [2]
(1-2) 뒤         head --> [H] --> [3] --> [2] --> [1] --> (H로 돌아감)
```

*그림 3. 리스트 2, 1의 맨 앞에 3을 삽입하는 과정*

### 3.2 InsertRear

맨 뒤에 삽입하려면 마지막 데이터 노드를 찾아야 한다. 링크가 한 방향뿐이므로 첫 노드에서 출발하여 링크가 헤드 노드를 가리키는 노드에 이를 때까지 따라간다.

```cpp
ChainNode<T>* cur = head->link;   // (2-1) 첫 노드에서 출발한다
while (cur->link != head) {       // (2-2) 링크가 헤드 노드인 노드가 마지막 노드이다
    cur = cur->link;
}
cur->link = newNode;              // (2-3) 마지막 노드 뒤에 새 노드를 잇는다
newNode->link = head;             // (2-4) 새 마지막 노드가 헤드 노드를 가리킨다
```

데이터 노드가 $n$개 $(n \ge 1)$이면 반복은 $n - 1$번 실행되어 `cur`가 마지막 노드에서 멈춘다. 빈 리스트에서는 `cur`가 처음부터 `head`이고 `head->link`도 `head`이므로 반복이 한 번도 실행되지 않으며, 새 노드는 헤드 노드 뒤에 삽입된다. 이 경우 맨 뒤 삽입이 맨 앞 삽입과 같은 결과가 되며, 역시 빈 리스트를 따로 검사할 필요가 없다. (2-3)과 (2-4)는 순서를 바꿔도 된다. 새 노드의 링크에 넣을 값 `head`가 `cur->link`와 무관하게 정해져 있기 때문이다. 마지막 노드를 찾는 반복 때문에 시간 복잡도는 $O(n)$이다.

### 3.3 검색 위치를 1부터 세기

안내문의 예시 화면은 리스트 3, 2, 1, 2, 4, 6에서 4를 검색하면 "4 is at the index 5"를 출력한다. 4는 다섯 번째 노드여서 0부터 센 위치는 4, 1부터 센 위치는 5이므로, 예시 프로그램은 위치를 1부터 센다. 풀이 프로그램도 이에 맞추어 위치를 1부터 세어 출력한다. 3강 6.6절의 `CircularList<T>::Search`가 같은 규칙(위치는 1부터, 찾지 못하면 0)을 따르며, 헤드 노드의 `data`에 찾는 값을 넣어 두어 반복마다 비교를 한 번만 하는 감시값 검색이다. 같은 값이 여러 번 나오면 첫 노드부터 처음 만나는 위치를 돌려주므로, 2를 검색하면 4가 아니라 2를 출력한다.

## 5. 헤드 노드에 관한 질문

### 5.1 헤드 노드를 쓰는 장점

답은 다음과 같다. 헤드 노드를 두면 리스트가 비어 있든 비어 있지 않든 삽입과 삭제 연산이 같은 방식으로 이루어진다. 리스트에 원소가 하나도 없는지 따로 검사할 필요 없이, 언제나 헤드 노드 뒤에 새 노드를 삽입하거나 헤드 노드 바로 다음 노드를 삭제하면 된다. 이 일관성 덕분에 경계 경우가 크게 단순해진다. 원형 연결과 함께 쓰면 `for (p = head->link; p != head; p = p->link)` 같은 단순한 반복문으로 `NULL` 검사 없이 모든 데이터 노드를 순회할 수 있어 검색 루틴도 간단해진다.

요약하면 다음 세 가지이다.

- 리스트가 비어 있든 비어 있지 않든 삽입과 삭제의 처리 방법이 같아 처리가 간단하다.
- 언제나 헤드 노드 뒤에서 작업하므로 리스트가 비었는지 검사할 필요가 없다.
- 원형 구조 덕분에 간단한 반복문으로 모든 노드를 순회할 수 있다.

이 답은 3절의 두 함수에서 그대로 확인된다. `InsertFront`와 `InsertRear` 모두 빈 리스트를 위한 분기가 없다. 덧붙이면 `head`가 가리키는 노드가 바뀌지 않으므로 어떤 연산도 리스트 포인터를 고칠 필요가 없고, 마지막 노드가 첫 데이터 노드가 아니라 헤드 노드를 가리키므로 맨 앞에 삽입할 때 마지막 노드를 찾지 않아도 된다(3강 6.3절). 또 헤드 노드의 데이터 필드를 감시값 자리로 써서 검색의 비교를 반복마다 하나로 줄일 수 있다(3.3절).

### 5.2 헤드 노드를 앞에 둘 때와 뒤에 둘 때

답은 다음과 같다. 헤드 노드를 앞에 두면 `head->link`가 언제나 첫 데이터 노드를 가리키므로 앞 삽입이 간단하고, 꼬리를 찾는 연산만 순회가 필요하다. 반대로 헤드 노드를 뒤에 두면 헤드 자체가 마지막 노드 역할을 한다. 그러면 뒤 삽입은 `head->link = newNode; head = newNode;`만으로 끝나는 $O(1)$ 연산이 되지만, 앞 삽입은 새 노드를 현재 첫 노드 앞에 연결한 뒤 꼬리 위치를 유지하도록 헤드의 링크를 갱신해야 한다. 실제로는 앞 삽입이 많으면 헤드를 앞에 두는 편이, 뒤 삽입이 많으면 헤드를 뒤에 두는 편이 효율적이다.

요약하면 다음 두 가지이다.

- 앞에 배치: `head->link`가 첫 번째 노드를 가리켜 앞 삽입이 매우 직관적이고, 꼬리를 찾을 때만 순회가 필요하다.
- 뒤에 배치: `head`가 마지막 노드가 되어 뒤 삽입을 $O(1)$로 처리할 수 있지만, 앞 삽입 때는 새 노드를 첫 노드 앞에 연결한 뒤 `head`가 마지막을 가리키도록 다시 설정해야 한다.

답은 헤드 노드를 뒤에 둔다는 것을 리스트 포인터가 마지막 노드를 가리키는 배치(3강 6.5절)로 보았다. 이 배치를 기준으로 두 가지를 보충한다. 첫째, 뒤 삽입은 `newNode->link = head->link; head->link = newNode; head = newNode;`의 세 문장이다. 답의 코드에는 새 노드가 첫 노드를 가리키게 하는 첫 문장이 빠져 있어, 그대로 실행하면 새 노드의 링크가 첫 노드로 이어지지 않아 원이 끊긴다. 둘째, 이 배치에서는 앞 삽입도 `newNode->link = head->link; head->link = newNode;`의 두 문장으로 끝나고 `head`는 그대로 마지막 노드를 가리키므로, 순회 없이 $O(1)$이다. 따라서 두 배치의 차이는 뒤 삽입의 비용에 있다.

| 배치 | 리스트 포인터가 가리키는 노드 | 앞 삽입 | 뒤 삽입 |
|:-----|:-----|:-----|:-----|
| 헤드 노드를 앞에 둠 (이 과제) | 헤드 노드 (그 링크가 첫 노드) | $O(1)$ | $O(n)$, 마지막 노드를 찾아야 한다 |
| 헤드 노드를 뒤에 둠 (답의 해석) | 마지막 노드 (그 링크가 첫 노드) | $O(1)$ | $O(1)$ |

*표 3. 리스트 포인터의 위치에 따른 삽입 비용*

## 요약

| 개념 | 핵심 요약 |
|:-----|:-----|
| 리스트의 구조 | `head`가 데이터를 담지 않는 헤드 노드를 가리키고, 마지막 노드의 링크가 헤드 노드를 가리키며, 빈 리스트는 헤드 노드가 자기 자신을 가리킨다. |
| `InsertFront` | 새 노드가 원래의 첫 노드를 가리키게 한 뒤 헤드 노드가 새 노드를 가리키게 하며, 순서를 바꾸면 리스트를 잃는다. |
| `InsertRear` | 첫 노드부터 링크가 헤드 노드인 노드까지 따라가 그 뒤에 새 노드를 잇고, 새 노드가 헤드 노드를 가리키게 한다. |
| 빈 리스트 | 두 함수 모두 빈 리스트에서 헤드 노드 뒤에 새 노드를 삽입하므로 따로 검사하지 않는다. |
| 복잡도 | `InsertFront`는 $O(1)$, `InsertRear`는 마지막 노드를 찾는 반복 때문에 $O(n)$이다. |
| 검색 위치 | 예시 화면과 3강 6.6절의 `Search`처럼 위치를 1부터 세고, 같은 값이 여러 번 있으면 처음 만나는 위치를 돌려준다. |
| 헤드 노드의 장점 | 빈 리스트의 분기가 없어지고, 리스트 포인터가 바뀌지 않으며, 감시값 검색과 `NULL` 검사 없는 순회가 가능하다. |
| 헤드 노드의 위치 | 리스트 포인터가 헤드 노드를 가리키면 뒤 삽입이 $O(n)$이고, 마지막 노드를 가리키면 앞 삽입과 뒤 삽입이 모두 $O(1)$이다. |

## 점검 문제

1. **링크의 순서:** `InsertFront`에서 `head->link = newNode;`를 `newNode->link = head->link;`보다 먼저 실행하면 리스트는 어떻게 되는가?

   <details>
   <summary>정답</summary>

   `head->link`가 새 노드로 바뀐 뒤에 `newNode->link = head->link;`가 실행되므로 새 노드는 자기 자신을 가리킨다. 헤드 노드에서 출발하면 새 노드만 계속 돌게 되고, 원래의 데이터 노드들에는 도달할 수 없어 출력과 검색에서 사라지며 메모리도 해제되지 않는다.

   </details>

2. **빈 리스트의 InsertRear:** 빈 리스트에 `InsertRear(7)`을 실행할 때 `cur`의 값과 반복 횟수, 실행 뒤의 링크를 쓰라.

   <details>
   <summary>정답</summary>

   빈 리스트에서는 `head->link`가 `head`이므로 `cur`는 `head`이다. `cur->link`도 `head`이므로 반복 조건이 처음부터 거짓이어서 반복은 0번 실행된다. 이어서 `head->link`가 새 노드를, 새 노드의 링크가 `head`를 가리키므로 헤드 노드와 노드 7이 하나의 원을 이룬다.

   </details>

3. **반복 횟수:** 4.1절의 실행에서 `InsertRear`가 세 번 불리는 동안 while 반복은 모두 몇 번 실행되는가?

   <details>
   <summary>정답</summary>

   데이터 노드가 $n$개일 때 반복은 $n - 1$번이다. 세 번의 호출 직전 노드 수는 3, 4, 5이므로 2 + 3 + 4 = 9번이다.

   </details>

4. **검색 결과:** 리스트 3, 2, 1, 2, 4, 6에서 2를 검색하면 왜 위치 2를 출력하며, 6을 검색하면 무엇을 출력하는가?

   <details>
   <summary>정답</summary>

   검색은 첫 노드부터 차례로 비교하여 처음 만나는 2에서 멈추고, 위치를 1부터 세므로 두 번째 노드인 2를 출력한다. 뒤쪽의 2(네 번째 노드)까지는 가지 않는다. 6은 여섯 번째 노드이므로 "6 is at the index 6"을 출력한다.

   </details>

5. **마지막 노드를 가리키는 포인터:** 리스트 포인터 `last`가 마지막 노드를 가리키는 원형 리스트(비어 있지 않음)에서 맨 앞 삽입과 맨 뒤 삽입의 코드를 쓰고 두 코드의 차이를 설명하라.

   <details>
   <summary>정답</summary>

   맨 앞 삽입은 `newNode->link = last->link; last->link = newNode;`이고, 맨 뒤 삽입은 여기에 `last = newNode;`를 더한 세 문장이다. 두 경우 모두 새 노드가 마지막 노드와 첫 노드 사이에 들어가며, 새 노드를 마지막 노드로 삼느냐(`last`를 옮기느냐)만 다르다. 둘 다 순회가 없으므로 $O(1)$이다.

   </details>
